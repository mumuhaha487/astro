Context Mode 是以 TypeScript 实现的 MCP 服务，面向 AI 编程代理，通过隔离工具输出、索引会话事件并配合钩子路由，降低上下文占用并支持会话延续。

## 项目做什么

项目针对编程代理在读取文件、网页或日志等工具结果时消耗大量上下文，以及对话压缩后丢失任务状态的问题。它提供 MCP 工具和平台钩子，将原始输出留在上下文之外，并通过检索相关记录帮助代理恢复工作；还倡导用脚本完成数据统计等分析，而非把大量原始数据交给模型处理。

## 与同类方案相比

README 描述了多类实际用途：沙箱工具可处理批量输入并只返回结果，会话事件写入 SQLite 并通过 FTS5 与 BM25 搜索，另提供索引、检索、诊断和统计等工具。项目声称示例中上下文用量可大幅降低，但这些数字来自 README，未在此独立验证；是否获益取决于任务、工具输出和配置。

## 设计与创新

项目将输出隔离、持久化会话事件检索、脚本化分析和跨平台路由组合在一个 MCP 服务中，并强调压缩后按相关性取回记录，而非把全部历史重新塞回上下文。README 将这套组合称为解决上下文问题的方式，但没有提供足以验证其相对既有方案创新程度的对比材料，因此创新优势尚无法确认。

## 适用场景

适用于使用 AI 编程代理处理大型代码库、批量检查文件、分析测试或访问日志、浏览器页面及 GitHub 问题等输出较多的工作。若团队使用 README 所列的 Claude Code、Gemini CLI、VS Code 或 JetBrains Copilot 等环境，可按对应方式配置 MCP 与钩子；其他平台是否适用需核对项目支持清单和具体版本。

## 谁会受益

当工具输出占用较多上下文，或较长任务会经历对话压缩时，该项目可能帮助代理减少携带原始数据，并从已索引事件中找回相关工作线索。其统计、诊断和索引命令也便于检查运行状态与检索资料。不过效果依赖代理正确调用工具、钩子正常运行及平台兼容，不能仅凭 README 的示例推断实际收益。

## 使用前需要注意

README 所述百分比和示例规模属于项目自述，无法据此确认普遍效果或独立基准表现；也未展示对不同模型、任务及平台的系统评测。持久化索引会涉及本地数据保留与清理，README 提到可清除索引，但用户仍需评估敏感数据处理方式。安装步骤和运行时要求因平台不同而异，兼容范围及部署细节应以实际版本验证；与其他产品的优劣目前无充分依据判断。
