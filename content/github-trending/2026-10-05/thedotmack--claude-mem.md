claude-mem 是以 TypeScript 为主的智能体上下文记忆项目，通过会话记录、AI 摘要和检索，把相关项目历史带入后续会话，并提供本地服务与多层搜索流程。

## 项目做什么

项目旨在减少智能体会话结束后项目背景与既往工作的丢失。README 描述的流程包括自动记录工具使用观察、生成语义摘要、保存会话和观察数据，并在后续会话中检索和注入相关上下文；主要面向 Claude Code，也列出 OpenClaw、OpenCode、Codex 等集成场景。

## 与同类方案相比

README 所述设计把记录、存储和检索连接为自动化流程，并提供按搜索索引、时间线、完整观察详情逐层获取的方式，便于先筛选再读取内容。项目还提及 SQLite、全文与向量混合搜索、Web 查看器、可配置的上下文注入，以及用 private 标签排除敏感内容；实际效果和隐私边界仍需结合实现验证。

## 设计与创新

README 展示的主要设计特点是将生命周期钩子、常驻 Worker、持久化数据库及 MCP 搜索工具组合起来，并以渐进披露控制上下文读取粒度。文档还描述多层检索和跨会话记忆，但没有提供足以证明这些设计具有行业首创性或相较其他方案更优的材料，因此创新性和差异化尚无法验证。

## 适用场景

适用于需要跨多次会话延续项目背景的开发工作，例如让智能体回顾过去的决策、修复记录或工具操作；也可用于通过搜索和时间线查找历史观察。若部署在文档列出的 OpenClaw 等环境，可探索相应集成；不同宿主的安装方式、功能覆盖和运行条件应分别确认。

## 谁会受益

对于经常重启会话、需要重复说明项目背景的使用者，持久化并检索历史记录可能减少手动回顾和重复输入。搜索结果可先以简短索引呈现，再按需取回详情，便于控制注入信息量。是否节省时间或令牌取决于数据质量、检索相关性和使用配置，README 中的节省比例不能视为独立验证结果。

## 使用前需要注意

项目依赖宿主插件或集成、Node.js 等环境组件，并可能涉及 Bun、uv、SQLite 及 AI 提供方配置；部署与维护成本需按使用方式评估。记录内容的准确性、摘要偏差、检索遗漏、数据保留和敏感信息处理细节，不能仅凭 README 确认。README 中关于服务、试用和令牌节省的描述也未在给定材料中独立核实；竞品优势及实际性能尚无依据。
