REA 是一个以 TypeScript 开发的逆向分析工具，通过 MCP 和命令行把智能体连接到多类应用与二进制分析工具，并提供带证据和限制说明的分析结果。

## 项目做什么

项目旨在帮助用户在无法获取目标应用源码时调查其行为与实现。用户可让智能体或命令行分析 JavaScript/Electron 应用、网站、.NET 程序和原生二进制，并查看功能、函数、内存或反编译结果；README 还描述了 Android APK、固件区域检查和受控进程行为采集等工作流。REA 提供分析工具接入及调查流程，但分析结论仍受目标和后端工具能力限制。

## 与同类方案相比

README 说明分析可在本地进行，结果会附带证据、限制与未解决问题；部分静态分析无需运行目标应用。项目提供 MCP 与 CLI 两种入口、诊断命令、Evidence 导入导出与比较，以及针对匹配目标和参数复用快照的机制。安装配置会展示变更并要求批准，还支持备份既有配置。这些是文档所列的设计与功能，不能据此推断实际速度或分析准确率。

## 设计与创新

README 将 REA 描述为跨应用、脚本和原生二进制的统一 MCP，并强调围绕证据组织分析结果、为智能体提供调查工作流，以及连接多个现有分析引擎。不过，材料没有提供足以验证行业首创性或相对其他工具创新程度的对照评测，也未给出完整实现细节，因此这些内容应视为项目定位和设计取向，而非已经证实的独特优势。

## 适用场景

适用于在没有目标源码时调查应用功能，例如理解搜索流程、检查 Electron 应用结构或查看原生程序中的函数；也可用于从终端生成分析结果、保存并复用快照、比较 Evidence，或把历史源码作为独立参考。需要额外工具的场景包括 Hopper、Ghidra 或 IDA Pro 原生分析，JADX 静态 APK 分析，以及 Linux 上借助 Binwalk 和 Unblob 进行固件区域检查。各工作流的系统与工具要求不同。

## 谁会受益

如果用户需要把逆向结果纳入智能体辅助开发，REA 能提供从接入分析工具、执行调查到呈现证据的统一流程；熟悉 CLI 的用户也可单独运行分析和诊断命令。它适合将二进制或应用结构调查作为后续实现的参考，但 README 没有证明工具能够自动还原完整源码、保证行为解释正确，或替代人工验证。使用者应依据证据和未知项审查结论。

## 使用前需要注意

功能覆盖取决于平台、目标类型、分析引擎和版本；原生深度分析需要单独准备 Hopper、Ghidra 或 IDA Pro，Android 与固件工作流也有独立依赖。README 明确指出反编译得到的是伪代码而非原始源码，部分能力仅在特定系统和架构上经过验证，Windows Ghidra 支持标注为实验性。MCP 首次分析可能耗时，外部数据库变化也可能影响结果；文档没有提供统一的准确率、性能或竞品比较数据。
