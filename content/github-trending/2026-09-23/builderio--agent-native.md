Agent-Native 是 BuilderIO 开源的 TypeScript 框架，用于构建自带专用 UI 的智能体应用。它通过共享 action 层，让智能体与 UI 复用同一套能力、数据和应用状态，并提供认证、技能记忆、自动化和智能体团队等基础设施。

## 项目做什么

该项目的目标是解决智能体应用缺乏合适交互环境的问题。README 指出，编码智能体依赖上下文、工具、文件和预览等环境来呈现能力与结果，而知识工作同样需要这类环境。传统纯文本聊天框无法让人直观地检查、编辑、批准和分享智能体产出。Agent-Native 因此提供一套框架，让开发者把每项能力定义为 action，智能体作为工具调用，UI 则从代码调用，从而在保留自主性的同时提供可视、可操作的界面，并让智能体与 UI 共享数据与状态。

## 与同类方案相比

根据 README，其优势来自三点设计：一是共享 actions，智能体与 UI 走同一条调用路径，复用相同的校验、权限和实现，避免为两个表面重复开发；二是共享数据，智能体完成的工作会出现在 UI 中，UI 中的操作也能被智能体感知；三是共享应用状态，智能体可接收当前页面、选中记录或活动视图等 UI 上下文。README 还列出内置能力，包括智能体聊天、认证与权限、技能与记忆、自动化、智能体团队，以及生产可用 PostgreSQL、本地可用 PGlite 的后端。

## 设计与创新

README 强调的核心设计是 action 层复用：一个 defineAction 定义同时暴露给 UI、智能体、HTTP、MCP、A2A 和 CLI，智能体不通过模拟点击 UI 来工作，而是与 UI 调用同一 action 层。此外，框架将智能体与 UI 之间的数据和应用状态打通，使二者形成双向可见的协作环境。README 也提到可让多个专家智能体在同一工作区或跨连接智能体间委派任务。不过，是否属于行业首创、与同类框架相比的具体差异，仅凭现有 README 尚无法验证。

## 适用场景

README 展示的应用场景包括：会议、屏幕与语音记录的理解（Clips）；生成和细化交互设计（Design）；制作品牌演示文稿（Slides）；对数据提问并构建仪表盘（Analytics）；查找时间、安排事件和管理预约（Calendar）；邮件优先级排序、起草回复和跟进（Mail)；创建与整理品牌媒体（Assets）；起草、组织和发布内容（Content）；以及创建包含图表、线框和原型的可视化计划（Plans）。这些官方示例应用可作为开发者的起点或参考模板。

## 谁会受益

对希望构建智能体应用的 TypeScript 开发者而言，该框架提供了一条较完整的起步路径：通过 npx create 命令和模板快速初始化，用 action 定义能力，即可同时接入 UI、智能体、HTTP、MCP、A2A 和 CLI 等多个表面。内置的聊天、认证权限、技能记忆、自动化和智能体团队等模块，可减少自行搭建基础设施的工作量。仓库还提供多个开源示例应用，便于参考实际实现。README 声明项目开源并采用 MIT 许可证，但未给出性能、稳定性或生产验证方面的具体数据。

## 使用前需要注意

README 未提供性能、并发能力或资源消耗方面的量化数据，也未给出与其他智能体框架的对比，因此相关优势尚无法验证。项目主要面向 TypeScript 生态，使用其他语言的团队可能不适用。虽然提到可自带 LLM、SQL 数据库、工具和基础设施，但未说明支持哪些具体模型供应商或数据库版本。内置能力多以链接指向官方文档，README 本身未展开实现细节。此外，示例应用的实际完成度、框架的成熟度和长期维护情况，仅凭 README 也无法确认。
