Project NOMAD 是离线优先的知识与教育服务器，基于 TypeScript 开发，通过 Docker 编排 Kiwix、Kolibri、Ollama 等容器化工具，在自有硬件上提供维基百科、课程、地图和可选本地 AI。

## 项目做什么

项目旨在让用户在自己的硬件上运行一个自包含的离线知识与教育服务器，从而在无互联网或网络受限的环境中持续获取信息、学习资源和工具。它通过管理界面和 API 自动处理大量容器化应用的安装、配置与更新，降低离线知识库的部署门槛，使用户无需手动维护 Kiwix、Kolibri、Ollama 等组件即可搭建可长期使用的离线信息站点。

## 与同类方案相比

项目将多种离线资源与工具集中到一个管理界面中，并通过 Docker 自动处理安装、配置和更新，减少了用户手动维护多个独立服务的负担。它支持 Debian 系操作系统和浏览器访问，可无需桌面环境运行；安装脚本基于终端，也提供 Docker Compose 模板供高级用户自定义。内置的更新机制、安装向导、内容选择器和应用目录进一步简化了首次部署与后续扩展，但这些优势的实际表现仍需结合具体硬件与网络条件验证。

## 设计与创新

NOMAD 强调的不是极简硬件，而是把离线知识与可选本地 AI 组合在一个自带管理层的 Docker 编排系统中。它通过内置的 Supply Depot 提供一键应用目录并允许运行自定义容器，同时内置自动更新决策逻辑和 dry-run 测试命令，可模拟升级窗口、冷却期与预检条件而不真正触发更新。这些集成方式在 README 中有较详细描述，但相较同类项目的具体新颖程度尚无法仅凭现有材料验证。

## 适用场景

适合在无互联网或网络不稳定的环境中长期提供知识查询与学习资源，例如偏远地区、应急场景、学校教室、家庭离线服务器或移动部署。用户可在性能足够的硬件上启用本地 AI 助手，通过文档上传和语义检索构建私有知识库；也可只用轻量配置运行维基百科、电子书、课程与离线地图。对于需要多用户访问的场合，项目目前建议通过本地网络端口控制来管理暴露范围。

## 谁会受益

对希望在自己设备上保存并访问大量离线知识、课程和工具的用户，NOMAD 提供了一站式的部署与管理方式，省去了逐一安装和配置 Kiwix、Kolibri、ProtoMaps、CyberChef 等应用的麻烦。内置的安装向导、应用目录和自动更新选项降低了维护成本；本地 AI 与文档检索能力在支持 GPU 的硬件上可扩展使用场景。其实际实用性取决于所选内容体积、硬件性能以及对无认证访问模式的接受程度。

## 使用前需要注意

项目默认不包含身份认证，设计上不适合直接暴露到互联网，多用户权限控制尚属未来可能添加的功能，目前建议依赖网络层控制。安装需要 sudo 权限和安装期间的稳定互联网连接，主要面向 Debian 系系统，Windows 需借助 WSL2 且为社区支持路径。运行本地 AI 需要较高硬件配置，尤其是 GPU 和显存；所有可安装应用的资源占用会叠加。此外，README 未提供性能基准细节和与竞品的对比数据，相关优势无法独立验证。
