New API 是以 Go 编写的可自托管 AI 网关，统一接入多种模型服务，并提供协议转换、请求路由、访问控制、用量与成本管理及管理界面。

## 项目做什么

项目面向个人、团队及组织集中管理 AI 模型服务：将上游服务接入网关，再由应用或用户通过统一入口调用。它也支持在 OpenAI、Anthropic 和 Gemini 等接口形式之间转换请求与响应，减少客户端直接配置多个上游的需要。具体转换效果取决于模型、渠道和转换路径。

## 与同类方案相比

README 所列能力包括多上游渠道、模型映射与优先级及权重配置、重试和渠道亲和性，以及用户分组、细粒度权限和 API 密钥限制。另提供用量日志、配额、订阅、缓存计费和分层定价配置；这些能力有助于集中管理访问和核算，但实际效果取决于部署配置及上游数据。

## 设计与创新

现有材料可以确认项目把多协议接入、请求路由、权限管理、用量核算、网页控制台和异步任务插件纳入同一网关，并提供独立的 RelayKit 协议转换模块。README 未提供足以证明其相较其他项目具有独特创新或技术优势的对比资料，因此无法据此判断其创新性排名或领先程度。

## 适用场景

适用场景包括团队共享已获授权的模型 API、在不同上游之间切换而尽量避免逐个调整客户端，以及搭建私有的多模型服务。组织也可用控制台管理渠道、模型、用户和审计记录，并在上游与渠道支持的前提下调用图像、音频、嵌入、重排、实时或插件任务接口。

## 谁会受益

对于需要一个集中入口连接多家模型服务的使用者，该项目提供从接入配置到客户端调用的完整路径，也具备 Docker、本地 SQLite 起步和 PostgreSQL、MySQL 等部署选项。请求日志、配额与价格配置可辅助用量管理；是否适合生产环境仍需结合实际安全要求、运维能力及上游接口兼容性评估。

## 使用前需要注意

协议转换并不保证不同服务的工具、字段和多模态能力完全对应，WebSocket 也要求上游和渠道兼容；功能可用范围受模型及配置影响。生产部署需要妥善设置密钥、数据库、HTTPS、代理和备份，多节点还需共享数据库及认证相关密钥。项目说明仅适用于依法授权的接入，并标注 AGPLv3 及附加归属要求；部署和再分发前应核对完整许可文本及适用义务。
