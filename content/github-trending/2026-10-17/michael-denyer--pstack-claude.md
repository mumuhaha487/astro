pstack-claude 将 pstack 工作流移植到多种 AI 编程助手环境，提供任务路由、规划、委派与验证相关技能，并支持按角色配置模型和推理设置。

## 项目做什么

项目旨在让 Claude Code、Codex、GitHub Copilot、Pi 等不同代理环境使用 pstack 的工作流。用户可通过 poteto-mode 描述目标，由其选择相应流程；README 描述的流程涵盖复现问题、调查原因、委派实现和重新验证，也列有规划、功能开发、重构及发布等场景。

## 与同类方案相比

README 展示的实际特点包括多种安装方式、可复用的技能，以及在部分环境中提供自动路由。其工作流强调先复现、再调查和修复，并提供失败与通过的验证证据；项目还支持为不同角色设置模型和推理程度。上述特点来自项目说明，实际效果仍取决于所用环境和模型。

## 设计与创新

仓库将 Cursor 相关工作流移植并适配到其他代理运行环境，也说明会跟踪上游并维护具名策略分支。不过，现有简介和 README 未提供足以验证其相对上游或其他同类工具具有独特创新或效果优势的对照材料，相关创新程度尚无法确认。

## 适用场景

适用场景包括让编码代理处理可复现的缺陷、跨函数边界的修改、功能开发、重构、调查、原型制作及 PR 维护等。对于并发错误和测试难以覆盖的不变量，README 指向另一个独立的 agent-formal-verify 项目；这表明形式化验证并非本仓库所描述工作流的内置功能。

## 谁会受益

若团队已经使用 README 所列的代理环境，希望用较统一的步骤组织任务、委派工作并要求验证，项目可提供现成技能和安装指引。对于希望按角色选择模型、调整推理设置或在多个会话中复用工作流的用户，相关配置说明也具有参考价值，但不能据此保证输出正确或节省时间。

## 使用前需要注意

支持能力因运行环境而异：部分环境没有自动路由，需要用户点名调用技能或添加常驻指令；Copilot 还存在文档记录的版本与非交互会话限制。项目没有服务器或遥测，但技能读取的内容会发送给模型提供商。README 未给出独立评测结果，性能、安全性和相对优势无法据此验证。
