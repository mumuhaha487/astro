TUIOS 是一个用 Go 编写的终端复用器与窗口管理器，提供模态界面、平铺窗格、工作区、持久会话和面向编码代理的收件箱。它基于 Charm 技术栈，支持 kitty 图形协议，并可通过守护进程让会话在重启后存活、跨机器访问。

## 项目做什么

该项目旨在把终端打造成一个可组织、可持久化的开发工作台。它通过 BSP 平铺、多工作区、模态键位和命令面板管理多个终端窗格，并借助守护进程让会话在终端关闭或重启后继续存在。同时，它把运行在窗格中的编码代理作为一等公民，汇总其状态、待办问题和相互消息，帮助用户集中查看和处理多个代理的请求。

## 与同类方案相比

根据 README，其优势包括：采用事件驱动渲染，空闲时 CPU 占用接近零；支持 kitty 图形协议的无闪烁图像与视频透传；提供 vim 风格的模态操作和可自定义键位；守护进程支持分离、重连和会话复活；能跨 ssh 或 Tailscale 访问其他机器上的会话；代理状态、收件箱、审批和代理间消息形成统一管理面。这些描述来自项目自身文档，尚未与同类工具进行独立比较验证。

## 设计与创新

README 中提到的创新点集中在代理集成：窗格内运行的编码代理可上报工作、等待、完成或出错状态；所有会话和机器上的待处理事项汇总到一个收件箱，并可直接作答；支持多种代理 harness、代理间消息传递、按 git worktree 并行运行的代理舰队，以及通过 MCP 暴露控制面。此外，tmux shim 让依赖 tmux 的工具以 tuios 窗格运行，多窗格复制模式支持一次性搜索并汇总选中内容。

## 适用场景

适合在终端中同时管理多个编码任务或代理的开发者。典型场景包括：用平铺窗格并行运行测试、构建和代理；用工作区隔离不同项目；通过守护进程保持长时间任务并随时分离重连；远程 ssh 到构建机运行代理并在此处查看其收件箱；用多选复制模式批量提取多个窗格的输出；用 tape 脚本录制和回放终端工作流；以 SSH 或 Web 终端模式远程访问。

## 谁会受益

对于习惯终端工作流并需要同时协调多个终端与编码代理的用户，TUIOS 将窗口管理、会话持久化和代理状态汇总组合在一起，减少在窗口间切换和手动检查代理进度的成本。其跨机器会话、收件箱和审批功能在分布式或长时间任务中可能显著提升效率。不过，实际收益取决于用户是否采用其代理集成生态，且 README 未提供可量化的效率提升数据。

## 使用前需要注意

README 未说明许可证类型，需查看仓库确认。它列出的部分功能标注为实验性，例如 sixel 图形没有像素级裁剪，kitty 文本尺寸协议在回滚和窗口移动时存在已知问题。项目要求终端支持真彩色，kitty 图形或 sixel 为推荐而非必需。代理集成依赖安装和配置，且需要代理侧配合上报状态。性能优势如近零空闲 CPU 未给出独立测量数据，与其他同类工具的比较也尚无法验证。
