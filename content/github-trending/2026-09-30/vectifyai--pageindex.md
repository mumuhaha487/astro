PageIndex 是 VectifyAI 开源的 Python 项目，实现无向量、基于推理的 RAG。它用树结构索引替代向量索引，让大模型在树上推理检索，面向金融、法律等长篇专业文档，提供可追溯的上下文感知检索。

## 项目做什么

该项目旨在解决向量数据库在长而复杂专业文档上检索准确性不足的问题。传统向量 RAG 按语义相似度召回，而相似并不等于相关，容易漏掉相关但不相似的段落，并返回相似却不相关的片段。PageIndex 的目标是把检索建立在推理与上下文理解之上，为每份文档生成树结构索引，再让大语言模型像人类专家一样逐层定位到正确章节，从而支持金融报告、法律文本、监管文件、技术手册、医学文献与学术教材等场景。

## 与同类方案相比

README 自述的主要优势是不依赖向量数据库、不做分块，检索结果可追溯到明确引用，而非难以解释的黑盒召回；除查询本身外还能利用对话历史和领域知识等完整上下文。官方基准称本地索引每页约 0.001 美元，千页文档略高于一美元，9 到 1098 页文档索引耗时约 13 秒到 4.5 分钟；与整份 PDF 直接输入模型相比，在 52 页和 420 页文档上分别可省约 2.1 倍和 16.6 倍成本，805 页时则已超出上下文窗口。项目还宣称在 FinanceBench 上达到 98.7% 准确率。这些数字来自项目方自测，独立复现情况尚无法验证。

## 设计与创新

核心思路是把向量索引替换为层级树索引，并让大模型在树上有代理式地搜索，据 README 称受 AlphaGo 启发。流程分为两步：先为每份文档生成树结构索引，再由聊天模型沿树推理定位。项目称树结构本身从文档版面提取，索引模型只负责总结与精炼，因此索引阶段用基础模型即可，而检索阶段建议使用力所能及的最强模型。此外还提供 PageIndex Flash 快速树索引、面向多文档语料的文件级树索引层 PageIndex File System，以及把工具接入 OpenAI Agents SDK、Claude Agent SDK 等框架的能力。以上为其自述设计，是否构成相对同类方案的实质创新尚无法独立验证。

## 适用场景

README 给出的适用对象是金融报告、法律文件、监管申报、技术手册、医学文献、学术教材等长篇复杂专业文档。开源本地模式偏向文本型 PDF 与本地工作流，可用自己的模型密钥完成索引、检索与对话；云端模式则覆盖文本、扫描件与含图文档，并额外提供 OCR、图像理解、块级引用、元数据、文件夹与 MCP 服务。官方还描述了一个面向长专业文档的类人文档分析应用，以及通过文件系统层扩展到百万级文档语料的用法。

## 谁会受益

对需要在高价值长篇文档上做问答的团队，该项目提供了不依赖向量库的另一种检索路径，强调可追溯与可解释，便于核对答案出处。其两步接口较简单：安装 SDK 后提交文档获得 doc_id，再以自然语言提问；同一客户端可在本地模式与云端之间切换，云端仅需替换索引参数。对成本敏感的场景，README 称索引一次可复用，后续提问只读取推理到达的节点，因而查询成本不随文档长度线性增长；对已有代理框架的用户，也提供了将检索工具嵌入其中的方式。

## 使用前需要注意

README 未提供许可证信息，使用前需自行确认授权条件。多项关键结论来自项目方自测：98.7% 的 FinanceBench 准确率、每页约 0.001 美元的索引成本、13 秒至 4.5 分钟的索引耗时、以及相对整份 PDF 输入的 2.1 倍至 16.6 倍成本优势，均缺乏独立第三方复现，不宜直接外推。本地模式对扫描件与图像密集文档支持有限，OCR、图像理解、元数据、文件夹和 MCP 仅云端提供。检索质量依赖所选聊天模型，强模型成本更高。演示代码中的模型名称与更新日期疑似示例或占位，需要以官方文档为准。此外，README 未给出与向量 RAG 之外其他方案的对比数据，相关竞品优势无法验证。
