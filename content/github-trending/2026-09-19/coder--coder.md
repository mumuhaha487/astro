Coder 是自托管的云开发环境与 AI 编码代理平台：工作区用 Terraform 定义，经 Wireguard 隧道连接，空闲自动关闭，AI 代理在自有基础设施上运行。

## 项目做什么

该项目旨在让组织在自己的基础设施上提供云开发环境：工作区通过 Terraform 定义，可落在 EC2 虚拟机、Kubernetes Pod、Docker 容器等之上，并通过 Wireguard 隧道安全连接。它同时把编码任务委派给在自有基础设施上运行的 AI 代理，支持接入 Anthropic、OpenAI、Google、Bedrock 或自托管模型，并由控制平面统一管理模型治理、成本追踪与审计日志。

## 与同类方案相比

README 列出的主要优势包括：以 Terraform 声明式定义环境，便于复用与版本化；空闲资源自动关闭，据称可节省成本；开发者上手被描述为从数天缩短到数秒；AI 代理的执行循环在控制平面运行，工作区内不存放 LLM 凭据，每次操作都携带用户身份，并提供集中的模型治理、成本追踪和审计日志；模型供应商可自由选择，也可自托管。上述收益多为项目自述，README 未给出可核验的基准数据。

## 设计与创新

README 中较具特色的设计包括：用 Terraform 描述工作区基础设施，配合 Wireguard 隧道连接访问，以及把 AI 代理的执行循环放在控制平面而非工作区内，从而避免在工作区保存 API 密钥并保留用户身份与审计记录。不过 README 没有与同类自托管开发环境或 AI 代理平台做对照，也未声明这些做法属于首创，因此其创新程度尚无法验证。

## 适用场景

适合需要自托管开发环境的团队：希望把开发环境统一放在自有 AWS、Kubernetes、Docker 或类似基础设施上，并通过代码化模板批量交付；希望把编码任务交给 AI 代理，同时要求凭据不进入工作区并保留审计与成本核算；希望按需启停工作区以控制开销；在受限或内网环境中通过官方与社区模板、模块以及私有 VS Code 扩展市场等集成来搭建环境。README 也提到 Premium 面向大型团队。

## 谁会受益

对平台与基础设施团队而言，它提供了从模板定义、工作区生命周期管理到编辑器接入的一条链路，并给出安装脚本、二进制与安装程序，以及 PostgreSQL 13 及以上的生产部署路径。对关注安全与合规的使用者，控制平面集中处理模型认证、审计与成本统计，工作区内不保存 LLM 凭据。对个人评估者，可直接用内置数据库和 try.coder.app 访问地址快速试用。实际收益取决于自托管基础设施与团队规模，README 未提供量化效果。

## 使用前需要注意

README 未给出性能、并发规模或资源占用的量化数据，也未说明许可证的具体条款，仅在徽章与链接中指向 LICENSE 文件。生产部署需要 PostgreSQL 13 或更高版本以及外部访问 URL，否则会退回内置数据库与 try.coder.app 访问地址，仅适用于评估。部分功能（Premium）需付费且未在此 README 中展开。与同类方案的比较、AI 代理的实际能力边界以及自托管模型的兼容程度，均无法从本 README 验证。
