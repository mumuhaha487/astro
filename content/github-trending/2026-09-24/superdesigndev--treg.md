Treg 是一个面向 AI Agent 的工具注册与调用代理，用单一 token 即可访问超过 3000 个外部端点及团队自有 API、CLI 和技能，并可按次计费，官方托管在 treg.to，也可自托管。

## 项目做什么

该项目旨在解决 Agent 执行真实任务时所需工具分散、订阅昂贵且常被注册墙或私有接口阻挡的问题。它把第三方数据服务、广告平台、社交发布、爬虫、图像视频生成等端点集中到一个注册表中，让用户无需分别注册供应商即可按任务搜索并调用，同时支持团队把自己的 API 密钥、CLI 与技能注册为共享工具，由服务端统一注入凭证，调用方不必接触密钥。

## 与同类方案相比

据 README 描述，其优势在于单一 token 和统一 base URL 即可访问大量工具，调用按次计价且可从一分钱起，无需向供应商单独注册；用户自有密钥会优先于平台密钥且不计费，多凭证注入、OAuth 连接、CLI 服务和会话级 shell 等机制让团队能安全共享凭证。不过，这些优势主要来自项目自述，缺乏独立验证，性能、成本与安全性尚未在给定材料中量化。

## 设计与创新

README 提出的核心设计是“代理只做中继而不再建模上游”，认证在服务端注入，调用方从不持有密钥，从而能适应上游 API 变化。凭证阶梯为团队自有工具、团队存储密钥、已验证免费公共路由、平台密钥四级；按任务而非按厂商搜索工具、按次计价与 402 余额响应便于 Agent 自动处理。另有 Enrich Arena 用于比较不同厂商的丰富化结果，但这些机制是否在同类项目中独创，给定材料无法验证。

## 适用场景

适合需要快速为 Agent 补充外部能力的团队，例如查询反向链接与域名权重、寻找工作邮箱、社交趋势与发布、广告管理与创意、网页抓取、图像视频生成等，且不愿逐个开通供应商账户。也适合企业把内部 API 密钥、CLI 工具和 SKILL 技能集中注册，让所有成员的 Agent 共享调用而不接触凭证。自托管方案面向需要自行部署注册表的开发者。

## 谁会受益

对 Agent 开发者而言，它降低了接入外部工具的门槛：通过 treg catalog 搜索与试调用可快速验证能力，调用日志和余额接口便于审计与成本控制，Claude 插件、MCP 连接器和 llms.txt 等入口降低了接入成本。对团队而言，凭证集中管理能减少密钥扩散风险。但由于未提供实际运行数据、延迟或稳定性指标，实际有用程度仍需自托管或试用后评估。

## 使用前需要注意

README 明确说明多数能力依赖平台自身密钥或已验证公共路由，未定价端点会被拒绝而不是免费提供；平台并不会在多个供应商间自动选择或故障转移，选型需调用者自行决定。自托管需要 tmux、uv，运行服务还需安装 server extra，配置涉及 Fernet 密钥与数据库，存在一定运维成本。此外，材料未提许可证、SLA、安全审计或性能数据，这些方面无法验证。
