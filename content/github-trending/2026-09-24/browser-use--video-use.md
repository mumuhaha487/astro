video-use 是一个开源 Python 项目，通过聊天让 Claude Code 等编码智能体自动剪辑视频。它基于音频转录和按需视觉合成来理解素材，完成去填充词、调色、生成字幕与动画等任务，最终输出 final.mp4。

## 项目做什么

项目的目标是让编码智能体无需预设菜单或模板，直接通过自然语言指令完成视频剪辑。用户将原始素材放入文件夹后，在 Claude Code、Codex 等具备 shell 访问能力的智能体中进行对话，智能体负责转录音频、提出剪辑策略、等待确认后执行渲染，并将输出保存到 edit/final.mp4。整个流程强调智能体读取素材而非观看视频，通过文本和时间线图像辅助决策，实现无预设的内容自适应剪辑。

## 与同类方案相比

根据 README，video-use 的主要特点包括：智能体以文本转录为主要阅读方式，避免逐帧分析视频带来的巨大 token 消耗；转录由 ElevenLabs Scribe 完成，提供词级时间戳、说话人分离和音频事件标注；通过 timeline_view 按需生成胶片条、波形和词标签，只在决策点调用；剪辑过程包含策略确认和自评估循环，渲染后会在每个剪切边界检查视觉跳跃、音频爆音和隐藏字幕，最多修复三次再展示。此外，会话记忆保存在 project.md 中，便于后续继续编辑。

## 设计与创新

README 强调其创新在于让 LLM“阅读”视频而非“观看”视频：用音频转录作为主界面，配合按需生成的视觉合成图，将传统 30,000 帧约 4500 万 token 的噪声压缩为约 12KB 文本加少量 PNG。这与 browser-use 给 LLM 结构化 DOM 而非截图的思路一致。另一个特点是自评估循环，在渲染输出上对每个剪切边界运行 timeline_view，自动发现并修复问题。动画生成支持 HyperFrames、Remotion、Manim 或 PIL，并由并行子智能体分别处理。

## 适用场景

适用场景包括口播视频、蒙太奇、教程、旅行记录和访谈等任意内容类型，因为项目不预设内容类型。用户可将原始片段放入文件夹，通过对话要求剪辑成发布视频；也能从 VPS 或 Telegram 通过 Browser Use Box 常驻运行。支持从在线来源下载素材（需 yt-dlp）。智能体先盘点素材、提出策略，等待用户确认后生成 edit/final.mp4。也适合需要反复调整、跨会话继续编辑的长期项目，因为 project.md 会保留会话记忆。

## 谁会受益

对于已经使用 Claude Code 或其他具备 shell 能力的编码智能体、并希望以对话方式完成视频剪辑的用户，video-use 提供了一条自动化路径。它减少了手动逐帧查看和编写复杂 ffmpeg 命令的需求，将转录、剪切、调色、字幕和动画整合到一个由智能体编排的工作流中。自评估和策略确认机制有助于在展示结果前发现问题。对于需要处理大量口播素材、去除填充词和死空间的创作者，该工具可能提高效率。其实际效果取决于转录质量、智能体推理能力以及渲染环境。

## 使用前需要注意

根据 README，项目依赖 ffmpeg 和 ElevenLabs API 密钥，转录和部分功能可能需要网络和付费服务。yt-dlp 为可选依赖，用于下载在线来源。自评估最多修复三次，超出后如何处理未说明。项目声称 100% 开源，但未提供许可证信息；性能对比和竞品优势没有具体数据支持，尚无法验证。LLM 从不直接观看视频，仅通过转录和 timeline_view 图像理解，可能遗漏纯视觉信息。此外，需要用户使用具备 shell 访问的智能体，对没有相关环境的用户存在门槛。
