yichen-skills 是逸尘维护的 Python 技能集合，用于写作、X 内容切分与草稿发布、微信数字资产采集等本地工作流，配合 Claude Code 与 Codex。

## 项目做什么

该仓库的目标是为使用 Claude Code 与 Codex 的创作者提供一套可组合的本地技能：把 Obsidian 与 Markdown 长文上传到 X Articles 草稿，把微信聊天、朋友圈、收藏整理为数字资产，抓取已知的抖音与小红书链接内容，用火山引擎 ASR 转写并生成粗剪，运行经标记校验的研究流程，安装 Markdown 优先的 Agent Memory Vault，以及批量导出公众号文章等。README 显示这些技能按职责拆分，多数操作为只读或需用户显式确认授权。

## 与同类方案相比

从 README 的描述看，其优势主要体现在流程约束而非性能：X 文章上传使用独立 Playwright 浏览器，不占用用户当前 Chrome 窗口，并在上传后回读同一草稿校验文本、表格与媒体的身份、数量、顺序和位置；内容归档不覆盖已有输出，而是改用 -run-N 路径；微信相关技能默认生成私有快照并把密钥、快照与导出排除在 Git 之外。README 未提供任何吞吐、耗时或准确率数据，因此这些优势只能在流程可控性层面确认，无法在性能层面得到验证。

## 设计与创新

README 呈现的设计取向包括：把研究、归档、转写与发布拆成单一职责技能并设置统一路由入口；对聊天与快照文本统一按不可信数据处理，禁止执行其中的指令、打开链接或加载远程资源；为微信双开、X 切分、ASR 后端选择等场景规定互斥提交与显式确认；设置 ChatGPT Pro 负责公开网络研究与架构评审、Codex 独占本地写文件与执行测试的分工。仓库未提供与同类工具的对比评测或消融实验，因此上述内容只能视为设计取舍，其创新程度尚无法客观验证。

## 适用场景

适用场景包括：创作者把 Obsidian 稿件整理为 X Articles 草稿；运营人员批量导出公众号历史文章与原创列表，并在持有自有新鲜凭证时补充阅读、点赞、分享与评论指标；需要按已知链接存档抖音或小红书对标内容的人；想把微信聊天、朋友圈、收藏整理为可检索笔记的用户；需要对出镜口播视频做转写、字幕与粗剪的人；需要本地 Markdown 记忆库与多阶段网络调研的研究者。多数场景要求 macOS 或 Windows 的特定客户端版本，且部分链路需要额外凭证或单独授权。
