Tinycast 是用 Swift 编写的原生 macOS 启动器，集成全局热键、剪贴板历史与窗口管理，并可运行 Raycast 扩展。

## 项目做什么

项目目标是给 macOS 用户提供一个体量小、完全原生的统一入口：一个全局热键唤出命令面板，把应用启动、文件搜索、剪贴板历史、计算与单位换算、快捷链接、Apple 快捷指令、代码片段、自定义 shell 命令、窗口管理、系统操作、日历会议、笔记与表情选择等日常操作集中到同一界面，同时通过设置导出与从 Raycast 导入来降低迁移成本。README 强调其免费开源、不含遥测、常驻后台仍保持较低资源占用，并将内存预算写入贡献规范。

## 与同类方案相比

依据 README，该项目的优势主张包括：使用 SwiftUI 与 AppKit 编写、无第三方依赖、不使用 Electron、不含遥测；README 自称常驻内存低于 100 MB，并支持直接运行已有的 Raycast 扩展，以原生 SwiftUI 渲染。功能覆盖面较广，从启动器延伸到剪贴板、窗口管理、系统操作、笔记与快捷指令，并通过 Homebrew cask 分发，另有测试版通道。需要说明的是，上述均为项目自述，仓库未提供独立基准测试或第三方评测，因此内存占用、响应速度等指标目前无法验证，也不宜据此与其他启动器直接比较。

## 设计与创新

README 中最具辨识度的主张是能够运行既有的 Raycast 扩展，并以原生 SwiftUI 渲染，这在同类原生启动器中较少被公开声称；但文档未给出兼容范围、渲染机制或 API 实现细节，实际能覆盖多少扩展、是否存在行为差异均无法验证。Quicklinks、Snippets 动态占位符、内联计算与汇率换算、从 Raycast 导入设置等功能在启动器品类中较为常见，仅凭现有材料难以判定为原创。项目对功能集采取克制、封闭的路线，并把内存预算写进贡献规范，这可视为一种工程取向，但其效果同样缺少公开数据支撑。

## 适用场景

适合运行 macOS 15 及以上版本、希望用一个热键完成高频操作的桌面用户：例如频繁切换与退出应用、按关键词查找文件与文件夹、回溯并重新粘贴文本或图片、用键盘调整窗口布局、快速运行 Apple 快捷指令、插入常用文本模板或执行自定义 shell 命令、查看下一场会议并一键加入、临时记录 Markdown 笔记、输入表情符号，以及在任意应用中改写选中文字。对隐私敏感、不愿安装 Electron 应用、或希望沿用既有 Raycast 扩展的用户也可能感兴趣。Apple 芯片与 Intel 机型、macOS 26 均有对应安装包，macOS 15 Sequoia 版本已标注不再维护，AI 相关功能默认关闭。

## 谁会受益

从 README 描述看，Tinycast 将启动、文件搜索、剪贴板、窗口管理、快捷指令、笔记等多种高频操作收拢到一个热键与一个面板中，可减少在多个工具之间切换的成本；支持从 Raycast 导入设置并运行既有 Raycast 扩展，有助于降低迁移门槛；对在意隐私与本地化的用户，README 声明的无遥测、本地匹配快捷键、零第三方依赖具有一定吸引力。项目还提供了开发文档、架构与设计系统文档、安全披露渠道和明确的贡献流程，并接受 GitHub 之外的赞助渠道，说明维护者有意长期维护。不过实际易用性、稳定性与内存表现仍需用户自行安装验证。

## 使用前需要注意

README 显示的限制包括：仅支持 macOS 15 及以上，其中 macOS 15 Sequoia 版本已不再维护；应用为自签名，若通过 DMG 安装需手动清除 quarantine 标记；用 Homebrew 安装需先信任第三方 tap。贡献流程要求先开 issue 并取得 approved 标记，未关联该标记的 PR 会被自动关闭，且功能集被刻意封闭，仅以「其他启动器也有」为由的请求不被接受。性能数据、Raycast 扩展兼容范围与稳定性均缺少公开验证；AI 功能默认关闭且需自备密钥或已安装账号；项目采用 AGPL-3.0 许可，涉及再分发或与闭源产品集成时需自行阅读许可条款确认义务。与其他原生启动器的横向比较在现有材料中没有数据支撑。
