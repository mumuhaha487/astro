Paperclip 是一个基于 TypeScript 的开源 AI 代理编排平台，提供 Node.js 服务器和 React 界面，用于管理多代理团队协作、任务调度、成本控制与治理，帮助团队像运营公司一样运作 AI 代理组织。

## 项目做什么

该项目的核心目标是解决多 AI 代理协作中的管理混乱问题。它允许用户定义业务目标，招募不同提供商的代理（如 Claude Code、Codex、Cursor、OpenClaw 等）组成团队，通过组织架构、预算限制、治理审批和心跳调度等机制，让代理团队持续自主工作。项目定位于为需要同时协调多个代理、追踪成本、审计工作并确保代理围绕统一目标执行的团队提供一站式控制平面，而非简单的单代理工具或工作流构建器。

## 与同类方案相比

基于 README 描述，Paperclip 的优势体现在对多代理编排中关键难点的处理：原子任务签出与预算执行防止重复工作和成本失控；持久化代理状态使代理在心跳间恢复任务上下文；运行时技能注入让代理无需重新训练即可学习工作流；治理带回滚保障配置变更安全；目标感知执行让任务携带完整目标链；可移植公司模板支持导出导入；真正的多组织隔离确保单部署多公司数据独立。这些特性针对了多标签页管理混乱、上下文丢失、成本失控等现实问题。

## 设计与创新

README 中强调的创新点包括：将 AI 代理管理抽象为“公司”模型，而非工具或框架，包含组织架构图、预算、治理和目标对齐；原子化执行结合预算强制，避免双重工作和过度支出；持久化代理状态与心跳机制，使代理能按计划唤醒并续接上下文；运行时技能注入允许动态学习；以及可导出导入的公司模板支持秘密擦除和冲突处理。这些设计在同类工具中可能具有差异性，但 README 未提供与竞品的直接对比数据，因此实际创新程度尚无法独立验证。

## 适用场景

适用场景包括：希望构建自主 AI 组织的团队；需要协调多种不同代理（如 OpenClaw、Codex、Claude、Cursor）朝向共同目标的用户；同时打开大量代理终端难以追踪进度的情况；需要代理 7x24 小时自主运行但仍要审计和干预的运营；需要监控成本并强制执行预算的组织；期望以任务管理器方式管理代理流程的团队；以及希望通过手机管理自主业务的管理者。不适用于仅有单个代理、需要代码审查工具、提示管理器或拖拽式工作流构建器的场景。

## 谁会受益

Paperclip 对需要管理多个 AI 代理协作的团队具有明显实用价值。它提供了任务系统、组织架构、心跳执行、预算控制、治理审批、多组织隔离等基础设施，减少了自行搭建任务管理、通信与协调机制的需求。其开源和自托管特性允许团队在自有环境中部署，无需依赖外部账户。对于已经依赖多个代理但缺乏统一管理界面的用户，该项目可帮助集中监控工作、成本和决策，提升代理运行的透明度和可控性，但实际效果取决于部署与配置的复杂度以及代理适配器的可用性。

## 使用前需要注意

根据 README 和仓库信息，存在以下限制：项目明确表示自己不适用于单代理用户，若只有一个代理则无需使用。它不是聊天机器人、代理框架、工作流构建器、提示管理器或代码审查工具，因此不能替代这些专用功能。它要求代理能够接收心跳，未提及不支持此类机制的代理如何集成。README 未提供性能数据、并发上限、资源消耗或与其他竞品的量化对比，因此实际扩展性和效率无法验证。许可证显示为 MIT，但未提及其他法律或合规细节。此外，作为较新的开源项目，其生态成熟度、社区支持和长期维护稳定性尚待观察。
