OmniGet 是一款 Rust 桌面下载与媒体工具，靠 yt-dlp 等引擎支持约 1800 个站点，并可播放课程、阅读 PDF/EPUB、管理音乐库。

## 项目做什么

该项目要解决的问题是把分散的下载流程收拢到一个图形界面里：用户不必记 yt-dlp 命令行参数，也不必为 Instagram、X、Pinterest、字幕等各自准备脚本或扩展。README 描述的目标是粘贴一个链接即可下载课程、视频、音乐、图片和种子文件，随后还能在同一应用内播放课程、阅读 PDF 与 EPUB、转录音频、转换格式并做间隔重复学习。它同时面向已购课程想本地保存的人、需要跨多平台收集媒体的人，以及不想打开终端的普通桌面用户，覆盖 Windows、macOS 与 Linux。

## 与同类方案相比

按 README 自述，优势集中在集成度与零配置：下载引擎 yt-dlp 和 FFmpeg 由应用自动安装并保持更新；提供安装包、便携模式、winget、brew 与多种 Linux 包格式；支持断点续传、失败退避重试并按站点自适应并发；可通过浏览器扩展传递 cookie 与 referer，从而下载登录后才可见的内容；剪贴板热键可在后台直接开始下载；下载完成后内置播放器、阅读器、笔记与闪卡可直接使用。此外项目声明免费、GPL-3.0、无账号无广告、不对下载内容做遥测，文件保存在本地。这些多为项目自述，缺少第三方验证。

## 设计与创新

README 提出的差异点包括：以原生提取器处理课程等特定平台，其余交给 yt-dlp，形成两种通道并存的结构；浏览器扩展不仅嗅探网络中的 MP4、HLS、DASH 流，还能深度搜索挂钩页面播放器，并可按真实站点而非顶级域名分组 cookie；下载之后附带播放、阅读、转录与学习工具，并列出 158 项工具、MCP 服务器与 Claude Code 插件、Telegram 插件、点对点传输等能力。但这些属于项目自我描述，材料中没有任何基准测试、代码级说明或第三方对比，因此其新颖程度和实际效果目前尚无法验证。

## 适用场景

适合的场景包括：把已购买或已订阅的课程整门离线保存并按小节续下；跨 YouTube、Bilibili、Instagram、TikTok、X、Reddit、Twitch、Pinterest 等平台批量收集视频、音频与图集；用磁力链接或 torrent 文件下载；在无法或不愿使用终端的电脑上完成上述操作；需要下载登录后可见内容而手动导出 cookie 太麻烦时；以及下载完想直接播放、读 PDF/EPUB 或做笔记的用户。反过来，仅在终端里要原始文件、不需要界面与附加工具的用户，按 README 自己的说法，直接使用 yt-dlp 更合适。

## 谁会受益

其实用价值主要来自降低门槛与减少工具切换：对不熟悉命令行的用户，它把 yt-dlp、FFmpeg、gallery-dl 等能力包装成粘贴链接、选清晰度、点击下载的流程；队列、续传、退避重试与规则化归档减少了大批量下载的人工干预；扩展传递 cookie 省去了手工导出登录态；内置播放器与阅读器省去了另装软件；多平台安装包与便携模式便于部署到普通电脑或 U 盘。需要注意的是，核心下载能力来自 yt-dlp 等上游项目，本项目的主要贡献偏向集成、界面与后处理流程，其稳定性与站点兼容性仍取决于上游。

## 使用前需要注意

给定材料存在明显缺口：README 在浏览器扩展一节的中途被截断，命令行、MCP、插件、聊天、LoL、隐私声明等目录所列章节内容未出现，因此这些功能无法核实。安装与运行方面，README 自承未购买签名证书，Windows 会弹 SmartScreen，macOS 可能提示应用已损坏并需要手动执行 xattr 与 codesign，Linux AppImage 在较新发行版上缺少 FUSE 2，且依赖 GStreamer 插件，缺失时窗口可能空白甚至崩溃。原生支持的课程平台仅列出少数几个。对于下载付费课程是否违反平台条款或涉及版权、是否处理 DRM，材料未作说明。9,500+ stars、相关话题下最受关注等数据也未在给定信息外得到验证，与竞品的比较同样缺乏独立依据。
