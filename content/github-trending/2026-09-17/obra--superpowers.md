Superpowers 是面向编码代理的技能框架与开发方法论，用可组合技能与初始指令让代理按头脑风暴、计划、TDD、代码审查等流程推进开发，并支持多种代理工具安装。

## 项目做什么

Superpowers 的定位是把一套软件工程方法论封装成编码代理可自动加载的技能，让代理在动手写代码前先澄清需求、形成设计文档与实现计划，再按任务拆解推进，并在过程中执行测试、审查与分支收尾。它试图解决的问题是：代理容易直接生成代码、缺少可重复的工程约束与验证步骤，导致过程不可控、质量难以保证。项目由 Prime Radiant 维护，README 称其面向 Claude Code、Codex、Cursor、Gemini CLI 等多种编码代理提供安装方式。

## 与同类方案相比

README 描述的优点包括：技能会随会话自动触发，用户无需额外操作；流程覆盖头脑风暴、设计确认、任务级计划、子代理开发、TDD、代码审查和分支收尾，并把 TDD 的红绿重构写成强制要求；技能库还包含系统化调试、收到与提出代码审查、并行子代理分发等。安装渠道多样，涵盖多个编码代理的官方或自建插件市场，并按代理分别安装。仓库以 Shell 为主要语言，采用 MIT 许可证。这些优点来自项目自述，尚缺少公开的量化效果数据。

## 设计与创新

从 README 看，其做法是把开发方法论拆成可组合技能并绑定到代理会话启动、压缩等钩子上，再用初始指令确保代理主动查找技能；计划要求细到每个任务 2 至 5 分钟、含明确文件路径与验证步骤；子代理驱动开发为每个任务派发新子代理并做规格符合性与代码质量两阶段审查。这些设计是否在同类工具中首创，README 未提供对比或基准，因此无法验证；所谓自主工作数小时的说法也缺少实验数据。

## 适用场景

适合已经在使用受支持编码代理的个人或团队，希望把需求澄清、计划编写、TDD 与审查固化为默认流程；也适合企业环境，README 提到可联系 sales@primeradiant.com 获取商业支持、附加工具或管理式支出。对于需要跨多个代理工具协作的开发者，可按代理分别安装。若使用 Hermes，需注意其没有压缩后钩子，超长会话可能丢失引导；在 Pi 中，子代理与任务列表工具属于可选的伴随包，需要另行安装。

## 谁会受益

对使用者而言，它把工程纪律以技能形式内置到代理中，减少每次手工提醒写测试、先设计后编码的成本，并让计划文档、审查记录和分支决策有较统一的产出结构；技能库覆盖测试、调试、协作与元技能，便于按需扩展。不过 README 未给出时间节省、缺陷率或代码质量等可量化指标，因此实际收益取决于所用代理对钩子的支持程度与用户是否遵循流程，目前无法从仓库信息中验证其相对其他方法的优势。

## 使用前需要注意

限制包括：功能依赖宿主代理的插件与钩子机制，README 明确 Hermes 没有压缩后钩子，长会话压缩后可能不再触发技能，需重开会话；技能改动必须兼容所支持的全部代理，且官方一般不接受新增技能贡献，扩展性受维护方约束；默认会从官网加载带版本号的标志图以统计使用量，虽然可用环境变量关闭，但涉及遥测。此外，README 未提供性能、效果或与竞品的对照数据，部分能力如子代理在个别环境仍是可选包，需自行确认。
