OpenResearch 是面向研究场景的本地优先工作区，使用 Rust 编写，可将 Claude Code、Codex、OpenCode、Cursor 等编码代理转变为能查阅文献、提出假设、运行实验并产出研究产物的研究代理。

## 项目做什么

该项目的目标是把已有的编码代理接入研究流程，让代理不仅能写代码，还能围绕研究任务完成文献回顾、假设生成、实验运行与产物整理。README 将自身定位为研究代理与自动研究的本地优先工作区，强调项目和实验数据保留在本机，并可选连接远程或托管算力。它通过 CLI 命令和本地仪表板组织项目、实验、运行、日志与产物，同时提供技能安装命令，把 OpenResearch 能力注入受支持的编码代理。其核心目的不是替代具体模型或代理，而是为这些代理提供研究场景所需的工程化工作区、实验记录和运行环境。

## 与同类方案相比

README 列出的优势包括并行探索、可复现实验、证据上下文、代理可选、算力可选和本地所有权。每个研究方向可获得独立代理会话与隔离的 git worktree；实验变体以 git 原生实验树追踪，每次运行会保存记录提交的不可变归档；日志、差异、文件、结果和产物与产生它们的工作关联。用户可在 Claude Code、Codex、OpenCode、Cursor 之间按会话选择代理与模型，也可选择本地、自有基础设施或托管算力。官方发布版默认发送可关闭的粗粒度使用事件，且声称不包含代码、提示词、文件内容或路径、仓库名、令牌、邮箱以及项目与实验标识。

## 设计与创新

README 强调的创新点是把编码代理与 git 原生实验树、不可变运行归档、隔离 worktree 和自动研究循环结合起来，使代理能提出想法、修改代码、启动实验、检查证据并决定下一步。它还声称同一已提交源码快照可运行于本地、SSH、Slurm、Kubernetes、Ray、Hugging Face Jobs、Modal、Tinker 和托管算力，且不要求发布仓库。不过仓库简介和 README 没有提供与同类工具的对照评测、性能指标或独立验证，因此这些设计在多大程度上构成独有创新、是否优于其他研究代理工作区，目前尚无法验证。

## 适用场景

适用场景包括：研究者希望让编码代理并行探索多个研究方向，并为每个方向保留独立代码分支与实验谱系；需要把日志、差异、结果和产物绑定到具体运行以便复现和审查；希望在本地或自有集群上运行实验，同时用笔记本浏览器访问远端 GPU 主机；需要在同一界面中管理项目、实验、运行和文献查询；希望把 OpenResearch 技能安装到 Claude Code、Codex、OpenCode 或 Cursor 中；以及希望用自动研究循环持续提出假设并迭代实验。README 还提到可通过 orx discover 和 orx paper 查询关键词与论文元数据。

## 谁会受益

对于已经有编码代理使用经验、又需要管理实验谱系和证据链的研究人员或工程团队，该项目提供了把代理行为纳入可追踪工作流的可能。本地 SQLite 存储与 127.0.0.1 绑定意味着默认情况下代码和实验数据不必上传，创建项目或启动运行不会发布代码，这对关注数据边界或尚未公开的研究较有吸引力。CLI 命令覆盖项目查看、运行记录、日志、实验执行、文献发现和论文查询，配合本地仪表板可以形成较集中的操作入口。对希望在不同代理和不同算力后端之间切换的团队，它也提供了统一编排的潜在价值。但实际效率提升幅度取决于代理本身能力与任务类型，README 未给出可验证的基准数据。

## 使用前需要注意

README 未提供许可证信息、性能基准、与竞品的量化比较或第三方评测，因此无法确认其效率优势与创新程度。Windows 版本标注为 beta，且需要 Git for Windows；macOS 要求 11 及以上。远程模式下，远端服务绑定回环地址且没有应用层认证，同一主机上的其他用户可能访问该服务，存在安全边界限制。官方发布构建会发送可关闭的粗粒度使用事件，尽管声称不包含代码、提示词、路径、仓库名、令牌、邮箱或项目与实验标识，用户仍需自行评估是否关闭。项目依赖外部编码代理和模型，能力受这些组件约束；托管算力与账户相关能力可能需要注册 openresearch.sh 账号。
