MXC 是以 Rust 实现的策略驱动型隔离与执行项目，为 Windows、Linux 和 macOS 上运行不可信代码提供统一的容器请求、策略配置及多种隔离后端。

## 项目做什么

项目面向需要执行模型生成内容、插件或工具的应用开发者。应用通过 Rust、.NET 或 Node SDK 指定运行命令、容器类型和约束策略；MXC 校验请求、选择适用后端，并启动受隔离的工作负载。也可通过平台专用执行器提交 JSON 请求。

## 与同类方案相比

README 所述的实际便利包括：以统一请求模型使用不同平台的隔离后端；能够配置文件读写或拒绝规则、网络出口及部分 UI 访问；支持一次执行和持久容器生命周期操作。提供多语言 SDK、诊断文档与访问审计辅助策略编写。实际安全强度和易用性仍取决于所选后端及配置。

## 设计与创新

README 将策略驱动配置、多后端选择和 Rust、.NET、Node 类型化 SDK 作为项目设计特点，并列出进程沙箱、虚拟机等不同隔离路径。但仅凭简介和 README 无法验证这些设计相较其他方案的原创性或技术领先程度，也不足以确认各后端在策略语义上的一致性。

## 适用场景

适用于应用需要受控运行模型输出、第三方插件或工具命令的场景，也可用于配置网络默认拒绝的短时任务、管理需要反复启动的持久容器，以及通过诊断或审计辅助调整访问策略。审计模式会关闭工作负载的沙箱安全，README 明确警告不得用它运行不可信代码。

## 谁会受益

如果应用需要将不可信代码执行与自身进程隔离，MXC 提供了可嵌入应用的 SDK、按平台选择的后端以及 JSON 配置入口，可减少应用自行对接多种隔离机制的需求。其价值仍需结合目标操作系统、具体后端支持情况、策略需求和构建条件评估；README 提供了样例、API 参考与后端指南供进一步核查。

## 使用前需要注意

能力受操作系统、架构和后端约束：README 列明 macOS 使用 Seatbelt，其他平台各有默认和可选后端，部分 Windows 后端标注为实验性。它没有证明所有策略在各后端上的行为完全相同，也未提供可据以判断性能或安全保证的测试数据。构建还要求 Rust 1.93、Node.js 24 及所选后端的系统工具链。
