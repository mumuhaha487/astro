e2e 是面向 Web 与移动应用的 TypeScript 端到端测试框架：测试可用自然语言描述目标，由代理驱动应用，再以定位器和断言验证结果。项目提供 SDK、运行器、命令行及浏览器和移动端引擎，目前仍在迈向 1.0。

## 项目定位与要解决的问题

项目定位不是把整套测试交给不可见的 AI，而是将代理操作纳入常规测试流程：测试先通过 app 打开目标页面，再让 agent 执行语义化任务，最后用 screen 定位器和 expect 断言检查可验证结果。README 将其描述为适用于 Web 和移动应用的端到端测试框架，并允许只写传统测试、不使用代理步骤；因此，自然语言操作是测试能力的一部分，而非运行所有测试的前提。

## 核心能力

核心交互由三类对象配合完成：app 用于进入应用路径，agent.act 根据自然语言目标操作应用，agent.assert 检查语义层面的预期；之后仍可用 screen.getByRole 等定位器及 expect 对界面状态作明确断言。README 特别说明，若代理步骤由后续断言验证，该步骤的操作会被记录，后续运行在应用未变化时重放这些操作，不调用模型；测试不含代理步骤时也不需要模型。模型可由用户通过订阅、API 密钥或本地模型提供。

## 技术结构与实现思路

仓库将能力拆分为多个 npm 包：e2e 提供 SDK、测试运行器和 CLI；@e2e-dev/web 通过 Playwright 支持 Chromium、Firefox、WebKit；@e2e-dev/mobile 借助 agent-device 连接 iOS 模拟器与 Android 模拟器。另有 GitHub PR 评论报告器、供 Web 引擎使用的托管浏览器、托管移动模拟器，以及执行受边界约束的语义操作和断言的 decision 模型执行器。该划分体现了统一测试接口与平台执行、报告和模型执行能力的分层。

## 实际工作流程

入门从运行 npx e2e init 开始：初始化流程询问使用 Web 还是移动端引擎及模型提供方，并生成配置和示例测试。开发者在 TypeScript 测试中编排页面进入、代理任务和断言，再由运行器执行；具体后续步骤由项目文档说明。仓库还提供 Vite、Next.js、Expo 和 SwiftUI 的独立示例项目，并称其包含通过的测试套件。文档随 e2e 包发布，可在 node_modules/e2e/docs 离线读取，便于开发环境或编码代理查阅。

## 与同类方案的取舍

README 明确强调的设计特点，是将自然语言代理步骤与常规定位器断言放在同一测试中，并通过记录及重放，在应用未变化时避免后续运行的模型调用；这是项目方对行为机制的说明，并非经独立验证的性能结论。用户可选择订阅、API 密钥或本地模型，也可完全不在测试中使用代理。项目还提供 WebKit、Firefox、Chromium 及 iOS、Android 执行路径。README 未给出与其他框架的比较数据或速度、准确率基准，因此不能据此断言其整体优于其他方案。

## 值得关注的设计

项目把自然语言驱动的操作步骤与传统定位器、断言放在同一条端到端测试中。其独特设计还包括记录可由后续断言验证的智能体操作，并在应用未变化时重放，以减少后续运行中的模型调用；这是 README 描述的机制，实际效果仍取决于测试场景。

## 适用领域和具体场景

适用于需要验证完整用户流程的网页和移动应用，例如示例中的账单升级：先打开设置页面，再让智能体执行升级并检查账单预览，最后通过状态元素断言页面显示 Pro。项目支持 Chromium、Firefox、WebKit，以及 iOS 模拟器和 Android 模拟器；README 还列出 GitHub 拉取请求结果报告和托管设备相关组件。

## 哪些人会受益

主要面向用 TypeScript 编写应用或自动化测试、希望在测试中描述复杂交互目标的开发者和质量工程师。熟悉 Playwright 的网页团队可关注其浏览器引擎；涉及 Expo、SwiftUI 或其他移动应用的团队也可参考相应示例。采用智能体步骤的团队还需准备模型提供方、订阅或本地模型；不含智能体步骤的测试则无需模型。

## 上手、部署与集成

项目提供 npx e2e init 引导配置：选择网页或移动引擎及模型提供方后，命令会生成配置与示例测试。README 列出 Vite、Next.js、Expo 和 SwiftUI 的独立示例项目，并说明文档随 e2e 包提供，可在 node_modules 中离线阅读。组件按功能拆分为 SDK、运行器、命令行、网页及移动引擎、GitHub 报告器和托管执行相关包，便于团队按需了解其组成。
