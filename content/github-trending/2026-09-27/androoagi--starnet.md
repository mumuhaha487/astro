StarNet 是一个本地优先的桌面 AI 代理运行环境，用像素画空间站可视化真实运行状态。每个智能体拥有独立工作区、权限与记忆，通过本地 Node 边车执行真实模型调用与工具操作，状态落盘可查。

## 项目做什么

该项目旨在让用户以类似经营像素空间站的方式组织多个 AI 智能体，把房间布局直接映射为能力边界与协作流程。它解决的是同时运行多个有界智能体时的可见性、权限与状态可验证问题：每个智能体有独立工作区、对话记录、记忆和受限权限，运行并发进行。产品契约强调界面只呈现运行时可证实的真实状态，不模拟营收、完成工作、模型活动或花费，从而避免展示与后端事实不符的假象。

## 与同类方案相比

本地优先是其主要特点：密钥存放于操作系统钥匙串而非前端，状态、对话、记忆与账本留在本地工作区，只有运行智能体时才向模型提供商发起请求。支持自带 OpenRouter 密钥，也可通过 Anthropic、OpenAI、Google 的 OAuth 登录，并可用 Ollama 本地模型免费运行。可连接 Telegram、Discord、Slack、Signal、Matrix 等渠道远程交互，支持 Night Shift 无人值守运行并记录所有离桌操作，交付物进入 OUTBOX 成为真实文件。桌面版提供 Windows 与 macOS 构建。

## 设计与创新

其独特之处在于界面与运行时的严格对应关系：一个房间即一个按能力划分的团队，走廊即获授权的交接通道，放置的物件即真实的能力授权，用户画出的布局就是智能体实际执行的流程。Task Briefs 会在信息含糊时通过已连接渠道提出一个带选项的具体问题，而不是静默猜测。前端消费边车通过 localhost HTTP、NDJSON 和 SSE 发出的真实事件。还能从 OpenClaw 或 Hermes 的本地目录导入已有智能体，但密钥不会随迁移转移。这些机制在 README 中有具体描述，但与其他项目的差异尚无法验证。

## 适用场景

适合需要同时运行多个有界 AI 智能体并保持过程可见的个人或小团队。例如让多个智能体并发处理不同任务，各自在独立工作区中运行并受权限约束；在无人值守时启用 Night Shift，让智能体在可调整的明确范围内持续工作，离桌操作全部留痕可审。也可通过 Telegram、Discord 等渠道远程向空间站下达指令或回答问题。支持用 cron 调度周期性任务，通过 MCP 连接器或粘贴密钥、OAuth 方式接入外部服务，用语音听写输入并以统一声音输出。账本与预算持久化，可按实际花费控制。

## 谁会受益

对于想要本地掌控 AI 智能体运行、不希望把状态和密钥交给第三方托管的用户，该项目提供了可落盘、可审计的实际价值：密钥入钥匙串，状态与账本留在本地，花费和运行历史如实展示，交付物以真实文件形式落盘而非留在聊天滚动记录里。多智能体并发加独立权限的设计，有助于把复杂工作拆分给不同角色并限制其接触范围。支持自带密钥和 Ollama 本地模型，降低了使用门槛。发布流水线对 Windows 签名与时间戳、macOS 开发者 ID 与公证、更新器签名设有强制校验，说明项目对分发环节有一定要求，但不代表特定下载副本已在你的机器上验证。

## 使用前需要注意

仍处于早期发布阶段，Windows 是测试最多的桌面目标，macOS 实际覆盖较少；Apple Silicon 若误用 x64 包会跑在 Rosetta 2 下。Linux 仅有内部构建产物，不是受支持的公开发布目标。原生桌面外壳依赖 Rust 与 Tauri 前置条件，而边车只用 Node 核心模块。使用 Ollama 本地模型时，模型规模小于云端模型，长任务预期更慢更粗糙。界面不模拟任何未证实状态，意味着没有运行时事件就不会有可见产出。MIT 许可只覆盖代码，StarNet 名称、标志、空间站美术与精灵属于品牌资产，不在授权范围内，衍生版本必须使用自有名称、标志与美术。此外，README 中提到的相对优势与性能表现缺乏独立验证依据，尚无法核实。
