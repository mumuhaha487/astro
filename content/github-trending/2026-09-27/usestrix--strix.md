Strix 是 Python 编写的开源 AI 渗透测试工具，用自主智能体动态运行目标代码，发现并验证应用漏洞，支持 CLI、本地查看器与 CI/CD 集成。

## 项目做什么

该项目旨在用自主 AI 智能体替代或补充传统人工渗透测试与静态扫描，面向开发者与安全团队。它通过实际运行目标应用、执行侦察、利用与验证流程，生成带漏洞利用证明的发现，并提供修复建议和合规报告。README 明确将其定位为开源 AI 渗透测试工具，提供 CLI、GitHub Actions 集成、多智能体编排以及可选的云端和企业版本，帮助在开发流程中更早发现安全缺陷。

## 与同类方案相比

根据 README，Strix 的优势在于运行时验证漏洞并给出可复现的 PoC，而非仅依赖静态分析，从而减少误报；提供覆盖侦察、利用、后渗透的完整工具链，包括 HTTP 拦截代理、浏览器自动化、Shell 执行与 Python 漏洞运行时；支持多智能体并行协作与多种目标形式，如本地目录、GitHub 仓库、在线 URL、OpenAPI/Postman 集合；提供可操作的修复指引与报告，并可通过 headless 模式和非零退出码接入 CI/CD。

## 设计与创新

README 声称的创新点包括：以自主 AI 智能体团队模拟真实黑客行为，动态运行代码并通过实际 PoC 验证漏洞；Graph of Agents 多智能体编排，支持并行测试、共享发现和漏洞链组合；内置攻防工具链，覆盖从侦察到后渗透的完整流程；自动生成补丁与合规报告；可通过 SKILL.md 被外部编码代理调用。需要指出的是，这些多为项目自述，是否构成真实技术突破或与同类工具相比的具体优势，README 未提供第三方基准或对比数据，尚无法独立验证。

## 适用场景

适用于多种安全测试场景：对本地代码库、GitHub 仓库或线上 Web 应用进行黑盒、灰盒或带认证的渗透测试；基于 OpenAPI、Swagger 或 Postman 契约对 API 端点进行批量测试；在开发阶段通过 GitHub Actions 等 CI/CD 流水线对拉取请求做快速扫描，阻止不安全代码进入生产；用于漏洞赏金研究自动化并生成 PoC；也可通过 strix cloud 命令或 MCP 集成在云端或由编码代理触发扫描。

## 谁会受益

对开发者和安全团队而言，Strix 能把部分渗透测试工作自动化，缩短从发现到修复的周期，并在 CI 中提供非零退出码以便阻断有漏洞的合并。其开源版本可本地运行，结果保存在 strix_runs 目录，也可用 strix view 在本地查看，适合希望掌控数据流向的团队。支持多种 LLM 提供商和本地模型，降低了模型选型锁定。不过，实际效果高度依赖所选模型与提示配置，README 未提供量化测试或误报率数据，实际价值需结合具体环境验证。

## 使用前需要注意

README 未说明其漏报率、误报率或与同类工具的横向对比，也未提供性能基准，因此无法验证“快速”“准确”等描述。运行需要 Docker 环境和 LLM API 密钥，会产生模型调用成本并依赖外部模型服务；部分能力如云端自动修复、合规报告、SSO 等属于商业版本，开源版本是否包含全部功能需查阅文档确认。对目标系统进行动态利用可能带来法律与操作风险，需确保已获授权。README 中的示例命令、模型名称和版本可能随项目迭代而变化，且多智能体协作与自动修复的实际可靠性未经独立评估。
