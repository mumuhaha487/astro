该项目是一个面向逆向工程、授权渗透测试与安全研究的 AI 技能路由包，通过规则配置将 APK、二进制、前端 JS、CTF 等任务路由到对应技能模块和工具链，并支持多种代码 AI 客户端。

## 项目做什么

项目旨在解决 AI 代理在安全任务中工具选择与流程执行不一致的问题。当代理遇到 APK、ELF、前端 JS 加密、CTF 题目或渗透目标时，它通过 RULES.md 和 MASTER-ROUTING 等路由机制，将任务导向正确的技能模块（如 apk-reverse、ida-reverse、js-reverse），并检查本地工具索引，按需引导工具链自举，同时借助 case-init 建立作用域、时间线和证据链，最终输出报告和现场日志，避免代理盲目猜测命令。

## 与同类方案相比

依据 README，项目将路由规则集中在一个结构化配置 routing.json 中，并配有 175 个基准用例的回归测试，以及结构一致性和供应链固定检查，且在 Windows 和 Ubuntu 上通过 CI 验证。路由核心与客户端适配解耦，声明为客户端中立，支持 Claude Code、Codex、Cursor、OpenCode 等，客户端配置保持可选。此外，技能模块数量较多，覆盖 APK、移动端、二进制、JS、恶意软件、渗透、CTF、固件、供应链、LLM 安全等场景，工具索引可按平台刷新。

## 设计与创新

README 提及的潜在创新点包括：AI 自动路由任务到技能模块、按需自举工具链、自动进化经验库，以及将作用域门控置于执行动作之前的设计。然而，对于经验库自动进化的具体机制、工具链自举的实现方式，README 未展开说明，尚无法验证其实际效果或与同类项目的差异。项目宣称的 44 条路由规则（R0–R45）与配置文件中写明的 43 条规则（R0–R44）存在数字不一致，说明相关声明需要以实际文件为准。

## 适用场景

适用于需要 AI 辅助的安全任务场景，包括但不限于：APK 与 Android 逆向分析、iOS 移动端分析、二进制逆向（exe/dll/so/elf）、.NET 分析、前端 JS 加密参数逆向、DSL 虚拟机逆向、HTTP 抓包与请求重放、恶意软件与 YARA 分析、渗透测试与扫描、攻击链编排、案例证据审查、CTF 比赛、固件与 IoT 安全、补丁差分与 N-day 利用、Pwn 利用开发、EDR 绕过、API 与 GraphQL 安全、供应链与 SBOM、LLM 安全、OLLVM 反混淆、图表与报告生成。

## 谁会受益

对安全研究人员和 AI 辅助安全工作者而言，该项目的核心价值在于将分散的工具、技能和方法论组织成一个可路由的结构，减少 AI 代理选用错误工具或重复犯错的概率。它提供了可重复的工作流，包括作用域确认、技能路由、工具检查、案例证据链和报告输出，有助于提升任务执行的规范性和可追溯性。由于路由核心客户端中立，用户可以在多种 AI 编码客户端中复用同一套安全技能。项目还包含跨平台 CI 和回归测试，表明对路由正确性有一定验证。

## 使用前需要注意

README 未提供性能数据或与同类路由项目的对比，因此实际路由准确率、工具链自举成功率尚无法验证。项目声明支持多种客户端，但客户端适配的实际体验取决于各客户端自身的机制，README 未给出具体集成测试细节。路由规则数量在描述中前后不一致（44 对 43），可能影响用户对配置状态的准确判断。技能模块中许多依赖外部工具（如 IDA Pro、BurpSuite、Frida），其可用性和许可证受第三方约束，项目本身不保证这些工具可用。自动进化经验库的具体实现与效果未在 README 中说明，无法评估其有效性。
