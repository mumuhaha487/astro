ARTEX 是以 Go 为后端、Next.js 为前端的 LLM 多 Agent 渗透测试系统，使用 PostgreSQL 保存资产与探索数据，提供任务调度、过程留痕、审批和可视化功能。README 限定其用途为源码学习与本地隔离环境验证。

## 项目做什么

项目旨在让多个由大语言模型驱动的 Agent 协作推进安全测试任务：planner 规划并派发意图，worker 执行工具操作并记录结果，人在环路 Agent 支持交互。系统将资产事实和任务探索过程分别建模，并提供任务、漏洞、资产及执行过程的管理界面。README 明确禁止将其用于线上系统或生产环境测试。

## 与同类方案相比

按 README 所述，项目提供较完整的操作与管理链路，包括资产和探索图、任务活动流、工具调用记录、拦截审批、漏洞复测及覆盖视图；也支持从 ScopeSentry 同步资产。部署方式涵盖 Docker、本地编译和预编译包，前端可嵌入 Go 二进制。上述内容来自项目文档，实际易用性和效果尚未独立验证。

## 设计与创新

README 将双图数据模型、worker 间检索执行过程，以及 planner 跨轮次共享待办列表列为核心设计：探索图记录目标、意图、事实与漏洞的来源关系，资产图维护共享资产，锚点用于关联两者。文档称这些机制用于复用过程观察和按依赖推进多步任务；相较其他系统是否具有创新性，依据现有材料无法验证。

## 适用场景

依据 README 的用途声明，适合用于阅读和研究项目源码，或在本地隔离环境中验证相关技术原理。开发者也可在本地运行服务、测试前后端和检查 Agent 编排机制。虽然软件功能面向渗透测试工作流，文档明确禁止对线上网站、联网系统和生产环境发起扫描、探测或利用，因此不应据此将其描述为可用于实际授权测试的工具。

## 谁会受益

对研究多 Agent 调度、图式资产管理和安全测试过程记录的读者，项目提供了可检查的 Go 服务端、Next.js 界面、PostgreSQL 数据层及配置流程；文档还说明了测试命令、部署方式、LLM 接入和更新路径。是否适合具体研究或教学需求，取决于使用者对代码、模型服务及隔离环境的评估，README 未给出独立实测结果。

## 使用前需要注意

运行需要 PostgreSQL；探索功能还需配置 Anthropic 或 OpenAI 等 LLM 服务，实际效果与模型配置有关。部署和升级涉及数据库、代理及前端构建等配置，更新会重启服务并中断运行任务。README 说明复测记录尚未纳入漏洞报告导出或任务归档包，也未自动关联流量包。更重要的是，作者声明仅允许源码学习和本地隔离验证，并禁止线上及生产环境测试；性能、安全性和与其他方案的对比均无法从所给材料验证。
