mattpocock/skills 是一组面向编程代理的可组合技能，试图把需求澄清、领域语言、测试反馈和代码设计等工程实践，转化为可反复调用的工作流程。

## 项目定位与要解决的问题

项目不是独立的编程代理、应用框架或端到端开发平台，而是供 Claude Code、Codex 等编码代理使用的技能集合。作者将其定位为“真实工程”的日常方法：技能应当小巧、可调整、能组合，并把决策权留给使用者。README 将它与试图接管开发流程的 GSD、BMAD、Spec-Kit 作对照，认为后者会削弱控制权、令流程中的问题更难处理；这是作者说明项目动机时的判断，而不是经独立验证的比较结论。其覆盖范围从需求讨论延伸到实现、评审和复盘，重点在规范代理如何协作，而非替代工程师做所有决定。

## 核心能力

项目针对的核心问题不是单纯让代理写更多代码，而是处理开发中反复出现的错位、反馈不足和复杂度增长。需求尚不清楚时，grill-me 与 grill-with-docs 通过连续提问厘清设计分支；后者还把项目术语、领域模型和难以解释的决策沉淀为文档。实现阶段，tdd 强调先写失败测试，再按红、绿、重构推进；diagnosing-bugs 则把复现、缩小范围、形成假设、加仪表和回归测试组织成分阶段的诊断循环。面对设计退化，to-spec 会先询问涉及哪些模块，improve-codebase-architecture 则负责找出可能的模块深化机会。贯穿这些做法的主张是：以共同语言减少歧义，以及时反馈约束代理的盲目实现，并持续关注代码结构。

## 技术结构与实现思路

技能目录按 Engineering 与 Productivity 两个用途域组织，并按调用主体分为用户主动调用和模型可按任务需要调用两类。前者多承担流程编排，例如 ask-matt 路由到合适技能，implement 组织从规格到实现的过程；后者提供可复用的具体工作纪律，例如 tdd、code-review、domain-modeling 和 grilling。README 规定用户调用技能可以调用模型调用技能，但不能再调用另一个用户调用技能，这构成了其编排层级。技能之间由此形成可组合而非单一总控流程的结构：需求访谈、规格、工单、实现、评审可按需要串接。仓库简介称技能来自作者自己的 .agents 目录；README 没有提供运行时、内部协议或实现代码细节，因此不宜据此推断更底层的技术架构。

## 实际工作流程

首次使用时，用户可选择 Claude Code 插件或 skills.sh 安装。插件方式安装由市场管理的只读技能包，更新取决于 Anthropic 官方市场更新版本指针；skills.sh 则把文件复制到项目中，用户可以编辑，并在需要时手动更新。安装后需在每个仓库运行 setup-matt-pocock-skills，配置问题跟踪器、分诊标签和文档存放位置。典型工作流可从 grill-with-docs 澄清需求并形成术语与决策记录开始，再用 to-spec 整理规格、to-tickets 拆成带依赖关系的工作项，随后由 implement 或 implement-spec 推进任务，并在约定节点使用 TDD，最后进行代码评审。大型工作可借助 wayfinder 逐步解决决策问题；会话结束后，retro 用于提出改进代理工作环境的建议。各环节是可选的技能组合，并非 README 所描述的强制流水线。

## 与同类方案的取舍

项目的区别性主张集中在把工程实践拆成可编辑、可搭配的技能，而不是要求用户采用一套统一、封闭的项目流程。README 特别强调两种分发取舍：Claude Code 插件更接近订阅管理、文件只读；skills.sh 更接近复制进项目后由使用者拥有和修改。另一条特色是把共同领域语言直接纳入协作过程：grill-with-docs 和 domain-modeling 会围绕术语、GLOSSARY.md 与 ADR 工作，目标不止是让单次回答更短，也包括让命名和项目理解更一致。代码评审还被拆为标准符合度与规格忠实度两个检查轴，并称由并行子代理分别处理。README 所说的技能源于作者多年工程经验、能提升代码质量或降低思考成本，属于项目方的经验主张；来源没有提供基准测试或独立评估，不能据此断言其相对其他方法的实际性能优势。

## 值得关注的设计

项目把工程实践拆成可组合的代理技能，而非规定一套全包式开发流程。其核心是把需求澄清、共享领域语言、测试反馈和代码结构维护嵌入日常协作，并区分用户主动调用与模型按需调用的技能。

## 适用领域和具体场景

实际使用可覆盖从需求到交付的多个环节：先用 grill-me 或 grill-with-docs 追问需求，后者还能形成术语表和架构决策记录；再通过 to-spec、to-tickets 或 wayfinder 组织规格、任务和长期决策；实现阶段可结合 implement、TDD、调试和代码审查技能。triage 支持议题分类，retro 则用于回顾并改进代理工作环境。项目也提供原型、研究、教学及交接等非单纯编码场景的工具。上述用途来自 README 所列技能说明，实际效果仍取决于项目上下文与使用者判断。

## 哪些人会受益

目标用户是希望用编码代理开发真实应用、但不愿把工程过程完全交给自动化流程的开发者。技能强调工程师保留决策权，尤其适合需要反复澄清需求、维护领域术语、建立测试反馈回路，或关注代码结构长期可修改性的团队。个人开发者也可从单项技能开始，而不必采用整个集合。README 将技能描述为适用于任何模型；不过具体代理对技能格式、调用方式和工具的支持程度，来源没有逐一验证，采用者需要自行确认兼容性。

## 上手、部署与集成

项目提供两种主要安装路径，体现不同的维护方式。Claude Code 插件以受管理、只读的整套技能包形式安装，更新依赖 Anthropic 官方市场更新版本指针，README 提醒这可能比仓库发布晚数天或数周；skills.sh 则将选中的技能复制为项目中的普通文件，用户可以编辑，并在需要时手动拉取更新。使用者还需在目标仓库运行 setup-matt-pocock-skills，设置议题跟踪器、分类标签和文档保存位置。README 提醒不要同时采用两种安装方式，以免重复安装；Codex 原生插件则仍列为路线图事项。

## 限制与风险

技能提供的是流程指导，不等于自动保证实现正确或替团队完成工程治理。README 明确指出，架构扫描只能提出可深化模块的候选项，不能替老旧复杂代码库完成解缠；TDD、调试和代码审查也依赖项目已有的测试、工具及人工判断。安装方面，官方市场更新可能滞后，而可编辑安装不会自动同步上游改动；配置还要求用户先说明跟踪器、标签和文档布局。虽然项目方称技能适用于任何模型，但 README 未提供不同模型上的兼容性测试、效果评估或性能数据，因此不能据此推断各代理表现一致。

## 综合观察

这是一套把工程习惯转写为可调用工作单元的实践集合，特色在于围绕沟通失配、术语混乱、反馈不足和架构退化组织技能，而不是宣称某项模型能力突破。它的价值更可能体现在把访谈、规格整理、测试和审查等步骤带入代理协作流程；是否减少返工或提升代码质量，README 没有给出独立测量结果，应视作项目方提出的工作方法，而非已验证的性能优势。对希望保留控制权并按需吸收流程的工程师，它值得逐项试用；团队仍需评估技能是否契合自身规范，并承担更新与效果验证。
