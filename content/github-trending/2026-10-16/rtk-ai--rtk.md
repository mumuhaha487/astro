RTK 是用 Rust 编写的命令行代理，在 AI 编程工具读取 shell 命令输出前进行筛选和压缩，并提供多种工具集成与可选代理功能。

## 项目做什么

项目主要减少 AI 编程助手处理开发命令输出时接收的内容。它可将常见命令改写为对应的 RTK 命令，并对输出进行过滤、分组、截断或去重；README 还介绍了独立的 rtk-proxy，用于处理部分模型提供商 API 流量。项目简介所称的常见命令 token 消耗降低比例属于项目方描述，不能直接等同于账单降幅。

## 与同类方案相比

README 列出 100 多种受支持命令，覆盖 Git、语言工具链、测试、容器及云相关工具，并说明可集成多种 AI 编程工具。安装后支持通过钩子透明改写部分 shell 调用，也可显式调用 rtk 命令；此外提供统计与发现命令，用于查看项目记录的压缩情况。具体适用范围取决于工具集成方式和命令过滤器。

## 设计与创新

README 的主要设计特点是将命令改写、输出处理及可选 API 流量处理纳入可组合的 pipeline 配置，并按命令类型采用不同压缩策略。它也将命令输出代理与独立的 API 代理区分开来。不过，现有材料没有提供独立评测或与其他方案的对照，因而无法验证其创新程度或相对优势。

## 适用场景

适用于使用受支持 AI 编程工具、且经常让助手执行 shell 命令的开发工作流，例如查看 Git 状态与差异、搜索代码、运行测试或检查构建输出。希望观察压缩记录的用户可使用 gain 等统计命令；需要处理 API 流量的场景可另行评估 rtk-proxy，但其适配范围、配置需求和行为应以具体文档及实际环境为准。

## 谁会受益

如果开发任务会产生大量日志、测试结果或文件列表，压缩输出可能减少进入助手上下文的命令内容，并让结果更集中；是否改善实际费用或任务效果，取决于命令输出在整体输入中的占比及代理行为。RTK 提供多种集成入口和显式命令，便于在不同工作流中试用，但其收益应通过项目自己的运行记录和实际任务验证。

## 使用前需要注意

项目报告的 token 数量按字节数除以 4 估算，README 明确说明绝对数量近似，且命令输出压缩比例不等于整体输入 token 或账单降幅。钩子仅处理 Bash 工具调用，不会自动拦截内建的 Read、Grep、Glob 等工具；代理与各助手的集成能力也不相同。README 还说明不同发行版包含内容和许可证不同，实际采用前应核对版本与许可条款。
