Hyperswitch 是 Juspay 开源的可组合支付平台，使用 Rust 构建，支持连接 120+ 支付服务商，提供智能路由、收入恢复、保险库、对账等模块，兼容 SaaS 与自托管部署。

## 项目做什么

Hyperswitch 的核心目标是让企业以模块化方式自建或增强支付基础设施，避免被单一支付服务商锁定。它允许商家仅选用所需组件，如智能路由、重试策略、PCI 合规保险库或成本可观测性，而不必替换整个支付栈。同时支持从单一 Stripe/Braintree 集成过渡到多 PSP 路由，或保留现有 VGS/TokenEx 保险库进行架构重构，从而在控制权、灵活性和运维效率之间取得平衡。

## 与同类方案相比

根据 README，Hyperswitch 以 Rust 构建，强调性能与可靠性，并采用模块化架构，使企业可仅集成所需模块，避免供应商锁定。它内置 100+ 支付连接器，覆盖 Stripe、Adyen、Braintree 等主流网关，并提供智能路由、重试、保险库、对账和成本可观测性功能。支持 SaaS 托管沙箱、自托管 Docker 部署及 AWS/GCP/Azure 的 Helm 部署。但 README 未提供具体性能基准、竞品对比数据或独立第三方验证，因此相关优势尚无法客观验证。

## 设计与创新

README 中提到的创新点包括：以 Rust 构建的模块化支付基础设施，允许按需选用组件；智能路由基于预测授权率在 120+ PSP 间选择最优通道；收入恢复模块根据卡 BIN、地区、支付方式等调整重试策略；支持自带保险库以连接 VGS、TokenEx 而无需重新令牌化；以及成本可观测性工具用于审计和优化支付成本。此外，项目自我定位为“支付领域的 Linux”。但上述功能的实际效果和创新程度缺乏独立基准或对比数据支持，尚无法验证。

## 适用场景

根据 README，Hyperswitch 适用于以下场景：企业希望从单一 Stripe 或 Braintree 集成迁移到多 PSP 路由；商家计划替换支付网关，直接连接 TSYS、JP Morgan Payments 等收单机构；商家在重构支付平台时希望保留现有 VGS、TokenEx 保险库；需要统一管理多种支付、代付、欺诈和令牌化服务商；以及希望通过智能路由、重试、对账和成本可观测性来优化支付运营的团队。它同时提供 SaaS 和自托管选项，适合不同规模和合规要求的组织。

## 谁会受益

对于需要灵活控制支付栈的企业，Hyperswitch 提供了可组合的模块和丰富的连接器生态，可减少对单一 PSP 的依赖，并可能通过智能路由和重试提升授权率、降低支付成本。其 Rust 实现和模块化设计有助于提升系统可靠性和可维护性。开源模式允许自托管和深度定制，适合有技术能力且关注数据主权与合规的团队。然而，实际收益取决于具体业务量、集成复杂度和运维投入，README 未提供量化收益或客户案例，因此实际有用性需结合评估验证。

## 使用前需要注意

README 未提及 Hyperswitch 的明确局限性，但可推断：首先，作为自托管方案，企业需承担部署、运维、PCI 合规及安全责任，对团队技术要求较高。其次，虽然支持 120+ 连接器，但各连接器的功能覆盖和稳定性可能不均，需逐一验证。再次，智能路由和收入恢复依赖预测模型，其准确性和效果在 README 中无数据支撑。最后，项目采用 Apache 2.0 许可证，但未说明商业支持范围或 SLA，且未提供与竞品的客观比较，因此选型时需自行评估。
