Atlas 是一个用 Rust 开发的代码代理源控制工具，支持多代理并行编辑同一代码库，记录会话与提交关联的检查点，实现共享记忆与上下文注入。

## 项目做什么

Atlas 旨在解决代码代理在协作过程中上下文丢失、历史无法共享、知识分散的问题。它将每次代理运行记录为检查点，链接提交与会话，保留提示、工具调用和推理过程，便于长期查询。通过本地优先的存储和共享记忆机制，让多个代理（如 Claude Code、Codex）在同一项目中协同工作，避免重复解释和上下文重建。目标是让代理产生的代码变更具备可追溯的推理记录，而非仅靠提交信息。

## 与同类方案相比

根据 README 描述，Atlas 的优势在于多代理支持：可同时运行 Claude Code、Codex 及自有代理，共享记忆使切换代理不丢失上下文。检查点机制将提交与会话关联，即使在提交后重写历史（如 rebase）也能通过 patch-id 重新关联。本地优先设计确保代码、笔记和会话存储在用户机器上，密钥写入前即被清理。与其他编辑器相比，Atlas 自称从代理角度构建，但未提供具体性能或竞品对比数据，这些方面尚无法验证。

## 设计与创新

README 中提到的创新点包括：检查点概念，将提交链接回产生它的代理会话，并保留提示、工具调用和文件变更；共享代理记忆，使用本地嵌入和 HNSW 搜索，让不同代理读写同一语义索引；@提及本地解析，支持文件、符号、分支、提交、笔记、论文和过往会话，在发送提示前完成解析；会话交接机制，在首个消息中注入上次会话的精选事实包和尾部内容。这些功能在现有代码编辑器中较少见，但未与竞品直接比较，实际效果需验证。

## 适用场景

Atlas 适用于需要多个代码代理协作的场景，例如开发者在同一代码库上并行使用 Claude Code 和 Codex，通过共享记忆避免重复解释上下文。也适合需要长期追溯代理决策的团队，检查点可查询数月前的会话与提交关联。本地优先特性适合对隐私敏感的用户，代码和会话不离开本机。此外，知识库、研究论文集成和终端等功能可辅助开发者在单一窗口内完成编码、研究和版本控制。

## 谁会受益

Atlas 对使用代码代理的开发者有潜在价值：它减少了切换代理时的上下文重建成本，提供了代理行为的可追溯记录，并集成了编辑器、Git、终端、知识库和浏览器等工具。本地存储和密钥清理增强了隐私。然而，README 中的功能描述基于项目自述，实际易用性、稳定性和性能需通过实际使用评估。例如，多代理同时运行可能带来资源竞争，共享记忆的准确性和检索质量也未经验证。总体而言，它针对代理协作中的痛点提供了具体解决方案。

## 使用前需要注意

README 中明确或隐含的限制包括：仅支持 macOS 13+ 和 Windows 10+（x64），Linux 构建未测试；密钥清理功能虽在写入前运行，但未说明清理的完整性；匿名使用分析默认开启，可能涉及隐私顾虑；共享记忆依赖本地嵌入，资源消耗未说明；检查点在 squash 导致链接模糊时可能孤立而非猜测；长尾注册表代理的质量保证仍在进行中；未提供性能基准、竞品对比或许可证变更风险。此外，项目处于活跃开发，功能可能变动。
